## 一、Physical AI Agent 到底在解决什么问题

### 从拿水杯说起

你坐在椅子上，想喝桌上的水。你的大脑做了什么？

```
1. 看到水杯                        （感知）
2. 判断位置、距离、能不能够到       （空间理解）
3. 决定伸手去拿                     （规划）
4. 控制手臂肌肉收缩，手指合拢抓住   （动作执行）
5. 感觉到杯子滑了，加大握力          （反馈调整）
6. 拿起来送到嘴边                   （完成）
```

这六步就是 Physical AI Agent 要让机器做到的事。

### 与 LLM Agent 的本质区别

LLM Agent 的输出是文本/代码/API 调用。它说错了，改了重来，成本几乎为零。

Physical AI Agent 的输出是物理动作。它抓杯子时握力大了，杯子碎了。它开自动驾驶时判断错了，车撞了。

  物理世界的错误是不可逆的。

### 三大根本难题

1. 感知-动作鸿沟：像素怎么变成力矩？中间经过语义理解→空间理解→affordance→规划→运动控制，每一层表示格式都不同
2. Sim-to-Real 鸿沟：仿真器里百发百中，到真实世界就拉胯
3. 实时安全约束：机器人不能想 30 秒再回答，必须毫秒级反应

## 二、感知-动作链路与 VLA

### 完整链条

```
像素（摄像头 RGB 图像）
  ↓
语义理解：这是水杯，这是桌子，这是我的手
  ↓
空间理解：杯子在桌沿右侧 30cm，手距离杯子 15cm
  ↓
Affordance 推理：把手可以抓，杯口不能捏，底面要朝下
  ↓
任务规划：伸手 → 到达 → 抓住 → 提起 → 送向嘴边
  ↓
运动规划：肩关节旋转 30° → 肘关节伸展 45° → 腕关节调整...
  ↓
动作执行：6 个电机分别输出 X N·m 力矩
  ↓
触觉反馈：指尖压力 0.3N，杯子在滑动 → 加大到 0.5N
```

每一层箭头都是一次"表示转换"，从像素到力矩的格式完全不同：

- 感知层：RGB 像素（H×W×3 矩阵）
- 语义层：离散概念（"杯子"）
- 空间层：连续坐标（x=0.3, y=0.15, z=0.5）
- 规划层：符号序列（step1→step2→step3）
- 动作层：连续控制信号（6维力矩向量）

### 两条技术路线

**路线一：端到端 VLA**
- 一个模型直接从 RGB 像素 + 语言指令输出关节控制信号
- 中间不做显式空间理解和规划，全靠模型隐式学会
- 代表：RT-2、OpenVLA
- 优点：信息无损传递
- 缺点：不可解释、数据效率低、OOD 性能坍缩

**路线二：分层架构**
- 感知用 VLM，规划用 LLM，动作执行用小策略网络，显式接口连接
- 代表：RoboBrain、ACE-Brain
- 优点：可独立调试、可注入人类先验
- 缺点：层间信息传递有损耗

### 人脑的启示：Dual-System

人脑既不是端到端也不是分层，而是两条并行通路：

```
快速通路（System 1）：像素 → 运动皮层 → 肌肉
  不经过语言，不经过显式规划，毫秒级
  抓熟悉的杯子、躲避飞来的球、走路

慢速通路（System 2）：像素 → 语义理解 → 空间推理 → 规划 → 运动
  经过意识，经过符号化思考，秒级
  抓危险物品、规划复杂操作、学习新技能
```

关键：两条通路不是串行而是并行耦合。手在动的同时慢速通路仍在跑，随时可以介入。感知和动作是耦合的闭环，不是开环。

### 2026 年趋势：走向混合

- DSWAM：双系统 WAM，快速通路做视频世界建模 + 慢速通路做语言级规划
- TypeGo：LLM 不在关键路径上，只在需要时介入
- ACE-Brain：理解→规划→执行→监控→改进的完整闭环

### 早期走分层路线的原因（纯技术限制）

1. **数据**：端到端需要海量"像素+指令→动作"配对数据。文本在网上爬，机器人数据得用真机遥操作录制，一天录不了 50 条
2. **算力**：2020 年前 Transformer 塞进机器人控制回路做实时推理不现实。分层可以把慢的 VLM 放高处做一次规划，快的策略网络放低处做高频执行
3. **可调试性**：端到端是黑盒。分层至少能定位"是感知错了还是规划错了还是执行错了"

2024 年后三个限制松动：Open X-Embodiment 数据集达百万级、VLM 推理速度满足实时控制、仿真器质量提升。所以端到端 VLA 爆发，但很快发现 OOD 性能坍缩——纯端到端没有慢速通路做显式规划。

## 三、延迟约束与硬件部署

### 人与机器人的延迟分层对比

```
                        人                    机器人
脊髓反射/电机PID       30ms (不经过大脑)      1ms / 1000Hz (专用芯片)
小脑/平衡控制           50-100ms              2-10ms / 100-500Hz (策略网络)
视觉反馈操作            100-200ms             40-100ms / 10-25Hz (VLA模型)
任务级规划              500ms-数秒            500ms-数秒 (VLM/LLM)
```

### VLA 模型实测延迟

```
模型              芯片              单步推理延迟        控制频率
──────────────────────────────────────────────────────────
7B VLA (bf16)    L4 GPU            62ms/step          ~16Hz
7B VLA (bf16)    H100              ~17ms/step(优化后)  ~60Hz
GR00T N1.7       A5000 GPU         ~160ms             ~6Hz (原生)
GR00T N1.7+πR²   A5000 GPU         ~40ms              ~25Hz (优化后)
GR00T+ElegantVLA  —                —                  13.8→26.3Hz
Cosmos3-Nano     8×H20 GPU         1.18s              <1Hz
```

### Action Chunk（动作分块）

VLA 推理要 100ms，控制要 25Hz（40ms/步），怎么办？

一次推理生成一"块"动作（如未来 16 步），快速执行这 16 步，同时并行推理下一块：

```
逐步推理：推理100ms → 执行40ms → 推理100ms → 执行40ms → ...
  实际频率：~7Hz

Action Chunk：推理100ms → 生成16步 → 执行640ms（期间推理下一块）
  实际频率：25Hz（推理被隐藏在执行背后）
```

两个致命问题：
- **感知-执行错位**：推理时看的是 t=0 画面，执行到第 16 步时 t=640ms，画面早变了
- **开环盲区**：整块执行期间是开环的，中途杯子滑了模型不知道

解决方案：
- **πR²**：分快慢通道。慢通道（视觉语言特征）异步更新，快通道（本体感觉/关节角度）每 tick 更新
- **Jetson-PI**：训练轻量级未来预测模块，推理时先预测未来画面再做决策

### 机器人芯片

```
芯片                  算力(TOPS)    内存      功耗     典型用途
──────────────────────────────────────────────────────────
NVIDIA Jetson Orin    275          64GB     15-60W   主流机器人边缘部署
NVIDIA Jetson Thor    ~800         128GB    ~100W    新一代（2025）

```

### VLA 的 decode 与 LLM 不同

**方式一：自回归 token decode（跟 LLM 一样）**
- 代表：RT-2、OpenVLA
- 把连续动作离散化成 token，逐 token 生成
- 问题：动作是连续值，离散化有精度损失；112 个 token 逐个生成太慢

**方式二：Diffusion / Flow Matching（跟 LLM 完全不同）**
- 代表：π0、GR00T N1、CogACT
- 从随机噪声开始，通过多步去噪"雕刻"出连续动作
- 一次性输出整个动作块（7维 × 16步 = 112维向量）
- 典型 T=10-20 步去噪，每步一次前向传播

VLA 总延迟 = VLM 编码（看图+理解指令）+ N 步去噪（生成动作）

PhyAI 论文实测：pi0.5 的 action expert 占 8.8% 算力但 57.2% 延迟——大部分时间花在多步去噪上。

### 视觉 token 定制优化

VLA 输入：图像 token（上千个）+ 文本 token（几十个），视觉占 80%+。

但相邻控制步之间视觉变化很小（手稍微移动了一点）。

**Neural Introspection Gating**：门控网络判断"视觉变化大不大"，变化小直接复用上一步的 KV cache，跳过 ViT 编码。

**ElegantVLA**：学会"什么时候该重新看，什么时候可以不看"，把 GR00T 从 13.8Hz 提到 26.3Hz。

**WA-SpecDec**：把 LLM 的 speculative decoding 搬到 VLA diffusion 阶段——小 draft 模型生成候选动作，大模型并行验证。加物理感知：自由空间验证放宽，接近接触物体时验证严格。

### VLA vs LLM 延迟优化对比

```
LLM Agent：
  输入：文本 token（几百个）
  瓶颈：模型参数量大，decode 慢
  优化：KV cache、speculative decoding、量化

VLA Agent：
  输入：图像 token（上千个）+ 文本 token（几十个）
  瓶颈：① ViT 编码图像慢  ② diffusion 去噪步数多
  优化：视觉 KV cache 复用、去噪步数自适应、action chunk
```

### 延迟总览

```
                        延迟容忍度
                    ┌──────────────────────┐
     1ms            │ 100ms          1s    │  10s
     │              │    │            │    │
  电机PID        VLA策略      VLM规划      LLM推理
  (FPGA/ASIC)    (Jetson)     (Jetson)     (云端)
  1000Hz         10-25Hz      1-5Hz        0.1Hz
     │              │            │            │
  纯硬件         7B量化       7B-32B       70B+
  无AI          action chunk   显式规划     任务分解
```

核心张力：模型越大越聪明但越慢。7B 能做实时控制，70B 做不到。所以 dual-system 不只是生物学巧合，而是工程必然。

## 四、世界模型与 Cosmos

### 世界模型是什么

一句话定义：

  世界模型 = 一个学会了"如果我做动作 A，世界会变成什么样"的神经网络

输入：当前画面 + 拟执行的动作
输出：下一刻的画面（或状态）

就是机器人的"想象力"。

### 为什么机器人需要世界模型

纯 VLA 是"反射式"的——看到画面直接输出动作，不会"想一想后果"。

有世界模型，机器人可以预演：

```
方案 A：从上面抓 → 世界模型预测"水会洒" → 否决
方案 B：从侧面抓 → 世界模型预测"安全" → 执行
```

世界模型在不可逆的物理世界里提供"可逆的试错空间"。在脑子里摔杯子不花钱。

### 世界模型与 LLM 的关系

```
LLM：       给定前面的 token，预测下一个 token
世界模型：   给定前面的画面 + 动作，预测下一帧画面
```

本质都是自回归预测。但关键差异：

```
LLM：
  输入：文本 token（离散，词表 ~15 万）
  训练数据：互联网几万亿 token
  预测精度：大致对就行

世界模型：
  输入：当前帧（224×224×3 像素）+ 动作（7 维向量）
  输出：下一帧（224×224×3 像素）
  训练数据：视频 + 机器人轨迹（远少于文本）
  预测精度：物理上必须对（杯子位置差 2cm 就是抓到和抓不到的区别）
```

### Cosmos：世界基座模型

NVIDIA 做的不是某一个机器人的世界模型，而是"世界基座模型"（World Foundation Model），类比 LLM 基座模型：

```
LLM 基座模型（GPT、LLaMA）：
  海量文本预训练 → 学会语言一般规律 → 微调 → 特定任务

Cosmos 世界基座模型：
  海量视频预训练 → 学会物理世界一般规律 → 微调 → 特定场景
  （自动驾驶、机器人操作、工业仿真）
```

### Cosmos 架构演进

**Cosmos 1（2025.01）**

不直接预测像素（太耗算力且难保持物理一致性），而是在潜在空间做预测：

```
第一步：当前帧 → 编码器 → 潜在向量（8×8×256）
第二步：当前潜在向量 + 动作 → 预测下一时刻潜在向量 → 解码器 → 下一帧
```

训练数据：1000 万小时视频（驾驶、行走、物体操作、自然场景）。关键：大量行车记录仪和机器人操作录像（自带动作标注）。

**Cosmos 3（2026.06）**

从纯视频预测升级为"全模态世界模型"：

```
Cosmos 1：输入视频帧 + 动作 → 输出下一帧视频
Cosmos 3：输入语言 + 图像 + 视频 + 音频 + 动作序列（任意组合）→ 输出任意模态的未来预测
```

加语言的原因：纯视频世界模型只懂"物理会发生什么"，不懂"人想要什么"。世界模型需要同时处理"杯子是用来喝水的"（语义）和"杯子在桌子右侧"（物理位置）。

### 世界模型的三种用法

**用法一：数据扩增**
用世界模型生成合成视频，训练 VLA 模型。代表：DreamGen。

**用法二：规划评估**
VLA 生成候选动作 → 世界模型分别预测后果 → 选最优方案。代表：DSWAM、DynaWM、JEPA-WAM。

**用法三：闭环训练**
把世界模型当仿真器，在里面完整试错学习，不碰真实机器人。

### 世界模型 vs 传统物理仿真器

```
传统物理仿真器（Isaac Sim）：
  人类手写物理规则：F=ma、摩擦系数=0.3
  优点：物理精确
  缺点：只能模拟人类知道怎么描述的物理（刚体可以，布料很难）

世界模型（Cosmos）：
  从视频中学物理规律，不需要人类写规则
  优点：可以模拟任何视频中见过的现象（布料、液体、柔性物体）
  缺点：物理精度可能不够，可能有幻觉
```

NVIDIA 两条腿走路：Isaac Sim 做精确物理仿真，Cosmos 做学习型世界模型，互补。

### 世界模型三大未解难题

**难题一：长程预测漂移**

```
t=0: 真实画面
t=1: 预测（误差小）
t=2: 基于t=1预测再预测（误差累积）
...
t=100: 完全模糊或物理不一致
```

解决方案：
- JEPA-WAM：不预测短期局部未来，预测"阶段级全局未来"——跳过中间帧，直接预测里程碑
- RIFT："Keep the Future, Drop the Rollout"——保留未来状态预测，不做迭代式视频 rollout

**难题二：物理一致性幻觉**

模型从视频统计规律中学，不是从物理方程学。可能预测出杯子穿过桌面、水往上流。

解决方向：Newton 物理引擎——用精确物理方程约束世界模型预测。

**难题三：计算成本**

Cosmos3-Nano 在 8×H20 GPU 上单步 1.18 秒。世界模型需要预测多帧才有用，不能像 VLA 那样做实时闭环控制。

定位：离线规划器，不参与每步高频控制。又回到 dual-system：

```
快速通路（System 1）：VLA 模型，10-25Hz，实时控制
慢速通路（System 2）：世界模型，<1Hz，规划评估
```

### 刘洺堉访谈洞察

- **"备多则力寡"**：世界模型不要在所有维度都做冗余预测，过度冗余反而降低效果。Cosmos 3 用混合架构让不同模态有专门分支
- **"大模型比作中医"**：世界模型强调整体性和系统性，先"辨证"（理解整体状态）再"论治"（决定动作），而非头痛医头
- **"下一个 CUDA?"**：Cosmos 想做 Physical AI 的基础设施抽象层，类比 CUDA 之于 GPU

## 五、Sim-to-Real 鸿沟

### 仿真器为什么不真实

```
仿真器：杯子=完美圆柱体，重量200g，摩擦0.4，均匀光照，完美图像
真实：杯子有凹凸，重量198-203g，沾水摩擦变0.2，有划痕灰尘，有镜头噪声
```

gap 的本质：仿真器是你的"模型"，真实世界是"现实"。你没法建模你不知道的东西。

### 三类 Gap

**视觉 gap（看起来不一样）**
仿真器图像边缘锐利无噪声，真实图像有畸变有噪声 → VLA 在仿真训练见到的都是"完美图像"，到真实世界输入分布变了 → OOD 崩溃

**动力学 gap（动起来不一样）**
仿真器摩擦系数固定，真实世界摩擦随接触面/压力/温度变化。刚体 gap 小，柔性体 gap 大，流体 gap 巨大。

**传感器 gap（感觉不一样）**
仿真器关节编码器给 45.000°，真实编码器给 44.87° 或 45.12°，有噪声。触觉传感器有滞后和非线性。

### 四条解决路线

**路线一：Domain Randomization（域随机化）**

既然真实参数不确定，训练时就把参数随机化：摩擦 0.2~0.8、重量 150~250g、光照 0.5x~2.0x、颜色纹理随机。训练几百万次，模型学到的不是"某个参数下怎么抓"而是"不管参数多少都能抓"。

代表：DexSim2Real。

**路线二：System Identification（系统辨识）**

精确测量真实世界参数，调仿真器匹配现实。精度高但每换环境要重新校准。

**路线三：Real2Sim2Real**

```
Real2Sim：用真实机器人录少量视频 → VLM 辅助翻译成仿真轨迹
Sim：校准仿真环境 → 大量生成合成数据 → 训练 VLA
Real：部署到真实机器人
```

目前最流行。代表：AnyTask、AMD Real2Sim2Real。

**路线四：世界模型替代仿真器**

用从真实视频中学到的世界模型，天然没有 sim-to-real gap。但有物理一致性幻觉问题。最前沿方案是两者结合。

### 数据：Physical AI 最稀缺的资源

```
文本数据：写个爬虫一天爬几亿条 ← 几乎零成本
机器人数据：
  人类遥操作：一人一天录 50 条，10 万条需要 2000 人天
  真机自主探索：摔了坏了要修，更慢更贵
  仿真器生成：快且便宜，但有 sim-to-real gap
```

数据策略：

```
真实数据（少量，贵，质量高）→ 校准仿真器 + 验证
仿真数据（大量，便宜，有 gap）→ domain randomization 弥补
合成数据（世界模型生成）→ 覆盖仿真器无法建模的场景
```

NVIDIA 三层基础设施：Isaac Sim（仿真器）+ Cosmos（世界模型）+ Omniverse（3D 场景构建），目标让机器人数据从"几十万条"变成"几亿条"。

## 六、完整技术栈总览

```
Physical AI Agent 完整技术栈

感知层：
  摄像头 → ViT 编码 → 视觉 token
  问题：视觉 gap（仿真 vs 真实）
  解决：domain randomization + world model

空间层：
  视觉 token → 3D 几何 + 占据记忆
  知道什么在哪、能不能走、够不够得到

规划层（System 2，慢速通路）：
  LLM/VLM 做任务分解
  世界模型（Cosmos）做规划评估
  频率：<1Hz，只在不确定时介入

动作层（System 1，快速通路）：
  VLA 模型输出关节控制
  两种生成方式：自回归 token / diffusion
  action chunk 一次生成多步，异步执行
  频率：10-25Hz

反馈层：
  触觉传感器 → 快速纠错（滑了加力）
  视觉反馈 → 但有延迟，需要 KV cache 复用
  世界模型 → 离线预演后果

训练层：
  真实数据（DROID, Open X-Embodiment）← 少量贵
  仿真数据（Isaac Sim + domain randomization）← 大量有 gap
  合成数据（Cosmos 世界模型生成）← 弥补 gap

安全层：
  运行时动作授权（不可逆动作前检查）
  实时安全约束（力矩超限自动停止）
```
